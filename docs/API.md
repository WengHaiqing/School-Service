# 生产后端接口边界

当前小程序通过 `miniprogram/services/store.js` 在本地缓存中模拟完整业务状态。生产接入时，页面不应直接读写缓存，而应统一调用 HTTPS API。

## 建议模块

### 认证

- `POST /v1/auth/wechat`：使用微信登录 code 换取平台会话。
- `POST /v1/auth/phone/send-code`：发送短信验证码，按手机号、设备和 IP 限流。
- `POST /v1/auth/phone/verify`：验证手机号。
- `POST /v1/verification/student`：提交校园身份认证。
- `GET /v1/me`：获取脱敏用户资料和信用摘要。

不得相信小程序前端传来的用户 ID、学校认证状态、订单角色或金额。

### 任务

- `GET /v1/tasks`：按学校、校区、分类、关键词和截止时间检索。
- `POST /v1/tasks`：创建待审核任务。
- `GET /v1/tasks/:id`：查看公开详情。
- `POST /v1/tasks/:id/extensions`：延长未接单任务，服务端校验次数。
- `POST /v1/tasks/:id/accept`：事务性接单，防止多人同时抢到同一任务。

公开查询不得返回手机号、学生卡号、精确宿舍号等个人信息。

### 订单

- `GET /v1/orders`：查询当前用户参与的订单。
- `GET /v1/orders/:id`：服务端验证发布者/接单者权限。
- `POST /v1/orders/:id/submissions`：接单者提交完成凭证。
- `POST /v1/orders/:id/confirm`：发布者确认完成。
- `POST /v1/orders/:id/disputes`：发起争议并冻结后续结算动作。
- `POST /v1/orders/:id/messages`：发送订单消息并执行内容审核。

订单状态更新必须使用数据库事务、幂等键和乐观锁，不能只依赖前端按钮防重。

### 支付

- `POST /v1/payments/orders/:id`：创建适配实际业务场景的微信支付单。
- `POST /v1/payments/wechat/notify`：验签并幂等处理支付通知。
- `POST /v1/orders/:id/refunds`：由订单规则驱动退款。
- `POST /v1/orders/:id/settlements`：结算或分账，仅在支付产品允许的场景执行。

金额以服务端任务快照为准，使用整数“分”存储。支付成功、退款成功和结算成功都必须以微信服务端通知或主动查询结果为准。

### 内容和客服

- `POST /v1/reports`：任务、用户、消息举报。
- `GET /v1/support/tickets/:id`：查询客服工单。
- 管理端：任务审核、违规处置、申诉、争议、证据、支付对账和审计日志。

## 后台定时任务

- 下架到期且未接单的公开任务。
- 提醒即将到期的发布者。
- 对超过履约期未提交的订单进入24小时顺延期。
- 顺延期结束仍未提交时取消并触发合规退款流程。
- 提交完成24小时无异议时自动验收。
- 完成后7天从普通用户订单列表隐藏。
- 到达保留期限后执行删除或匿名化，不直接依赖前端删除。

## 安全底线

- 所有接口校验会话、角色、学校范围和状态转换。
- 学号、校园卡号、手机号、身份证明和支付标识加密或令牌化保存。
- 对客服和运营后台实施最小权限、二次验证和完整操作日志。
- 图片、文本和聊天内容执行机器审核与人工复核。
- 限制任务创建、接单、短信、消息和举报频率。
- 关键操作使用幂等键，防止重复支付、重复接单、重复退款和重复结算。
